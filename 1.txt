# And here's the research prompt I'd give another AI

This is deliberately **much more aggressive** than “find me GitHub repos.”

I want you to conduct an exhaustive technical research project for building an autonomous personal content-generation and distribution system.

Do NOT simply give me a list of AI video editors.

## THE PRODUCT

The system should work like this:

A user opens a mobile app and presses RECORD.

They place the phone somewhere and work normally for 1–3 hours.

They may talk naturally during the session.

They then press STOP and close the app.

From that point onward, the system should operate autonomously.

The phone should automatically upload/sync the recording in the background without requiring the user to manually transfer files.

The backend should:

1. Receive the recording reliably.
2. Store it.
3. Transcribe it.
4. Detect potentially valuable/interesting moments.
5. Extract candidate clips.
6. Edit those clips automatically.
7. Convert them into vertical short-form videos where appropriate.
8. Track the speaker/face and reframe when possible.
9. Remove excessive silence/filler where appropriate.
10. Generate accurate subtitles.
11. Generate title/caption/description/hashtags.
12. Classify which platforms each clip is suitable for.
13. Show the completed candidates inside a dashboard/mobile app.
14. Notify the user when processing is complete.
15. Let the user approve/reject/edit platform tags.
16. Automatically publish approved content.
17. Schedule publishing according to user-defined rules.
18. Record publishing status and failures.
19. Retry failed operations safely.
20. Never duplicate uploads/posts after a retry.

The user's desired interaction should eventually be:

RECORD → STOP → REVIEW → APPROVE

The system should do everything else.

## IMPORTANT PRODUCT PHILOSOPHY

This should behave like an autonomous system, similar in philosophy to a lead-mining automation system:

- User configures it once.
- System continuously performs repetitive work.
- User only handles high-value exceptions/decisions.
- Every process should have state.
- Every process should be retryable.
- Failed jobs should resume rather than restart.
- Duplicate work must be prevented.
- The system should improve from user feedback.
- The system should minimize unnecessary compute/storage/API usage.

Do NOT recommend n8n as the core architecture.

I want a proper application/backend architecture.
