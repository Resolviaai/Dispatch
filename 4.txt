### WHAT WE SHOULD NOT BUILD OURSELVES

This section is especially important.

The goal is not to create the most technically impressive system.

The goal is to create the smallest amount of original code necessary to make the autonomous personal content engine work reliably.

Here is the comprehensive architectural research and technical blueprint for building Relay. This system moves beyond basic automation; it requires durable state management, heavy media processing, and intelligent pipeline orchestration.

Given the complexity of scripting, timeline cutting, and visual packaging involved in a professional video pipeline, the goal here is to replace manual NLE (Non-Linear Editor) work with programmatic, retryable logic. We will avoid low-code tools for the core processing loop, opting instead for a hardened backend.

## 1. Capture, Upload, and Storage Ecosystem

**Mobile Camera / Recording**
Do not build a camera engine from scratch. The edge cases for thermal management, audio syncing, and background lifecycle are notorious.

* **Repository:** `mrousavy/react-native-vision-camera` (React Native) or fork the mobile layer of `mieweb/pulse`.
* **Recommendation:** Use React Native Vision Camera for the UI and frame control, but write a native bridge for continuous background service recording (Android `WorkManager` / Foreground Service).
* **Architecture:** Record in 10-15 minute rolling chunks. If the app crashes, you only lose the current chunk.

**Automatic / Background Upload**
Standard multipart uploads will fail on mobile networks. You need a protocol designed for connection drops.

* **Repository:** `tus/tus-js-client` (Client) and `tus/tusd` (Server).
* **Recommendation:** TUS is non-negotiable for this. It tracks byte-offsets. If a user walks into an elevator, the upload pauses and resumes at the exact byte when they reconnect. Run `tusd` in a lightweight Go container separate from your main backend.

**Storage**
AWS S3 is too expensive for egress when constantly pulling gigabytes of video to worker nodes.

* **Alternative:** **Cloudflare R2**.
* **Why:** R2 charges zero egress fees. For a system that constantly shuffles heavy video files between storage, transcription services, and FFmpeg workers, this saves massive operational costs.
* **Policy:** Set a bucket lifecycle rule to automatically delete raw `.mp4` chunks after 7 days, retaining only the final edited clips and the JSON metadata/transcripts.

**Real-Time vs. Post-Processing**
Attempting to process video on the mobile device while recording (hybrid/real-time) will destroy battery life, overheat the device, and risk OS-level termination.

* **Recommendation:** Pure post-processing. The phone’s only job is to record to local SQLite/disk and quietly push TUS chunks to the server in the background.

## 2. AI, Video Processing, and Assembly

**Video Transcription & Diarization**
Base Whisper lacks reliable word-level timestamps and speaker tracking.

* **Repository:** `m-bain/whisperX`.
* **Why:** WhisperX forces word-level alignment using Wav2Vec2 and integrates `pyannote-audio` for speaker diarization. It tells you exactly *who* is speaking and at what *exact millisecond* a word is spoken, which is mandatory for clean automated cuts.

**Moment / Highlight Detection**
Do not use heavy, expensive multimodal vision models for this layer. Video is too dense.

* **Architecture:** Extract the audio, run WhisperX, and pass the timestamped transcript to a large-context LLM (like Gemini 1.5 Pro).
* **Logic:** Prompt the LLM to identify "high-information density" blocks with a clear hook, body, and conclusion. Because you have the exact timestamps from WhisperX, the LLM simply returns an array of JSON objects containing `start_time`, `end_time`, and `reasoning`.

**Video Editing & Face Tracking**

* **Repository:** `ffmpeg-python` combined with `google/mediapipe`.
* **Why:** Auto-Editor is great for silence removal, but Relay needs semantic editing. Use MediaPipe’s Face Detection to scan the selected candidate clip (every 5th frame to save compute). Calculate a bounding box, apply a simple smoothing algorithm (like a moving average) to prevent jitter, and generate programmatic FFmpeg `crop` commands to convert 16:9 to 9:16 dynamically keeping the face centered.

**Caption Engine**

* **Repository:** `remotion-dev/remotion` vs. `libass`.
* **Tradeoff:** Remotion is beautiful but requires spinning up an entire Chromium headless instance to render frames, which is slow and compute-heavy.
* **Recommendation:** For V1, use a Python script to convert WhisperX JSON into a styled `.ass` (Advanced SubStation Alpha) subtitle file, and burn it in using FFmpeg in one pass. It is 100x faster and cheaper. Move to Remotion in V2 when you need complex animated overlays or dynamic branding.

**Content Packaging**
Use `jxnl/instructor` (Python/TypeScript) to force the LLM to return strict JSON matching your schema for Titles, Descriptions, Hashtags, and Platform tags.

## 3. Operations, Delivery, and Learning

**Backend Workflow Engine (CRITICAL)**

* **Repository:** `triggerdotdev/trigger.dev` (v3).
* **Why:** Standard queues like Redis/RQ or Celery will timeout on a 45-minute FFmpeg rendering job. Trigger.dev v3 allows you to write standard TypeScript code that can run for hours, pause, wait for webhooks, and resume without holding a serverless function open. It handles retries and idempotency natively, making it the perfect orchestration layer.

**Platform Classification & Publishing**

* **Repository:** `ayrshare` (API) or `alfredang/socialmediapost`.
* **Warning:** Direct official APIs for Instagram and LinkedIn require constant OAuth token refreshes and are easily blocked.
* **Recommendation:** Use a third-party unified API like Ayrshare. It abstracts the token nightmares and rate limits. The minor cost is worth avoiding the engineering headache of maintaining 5 different social platform SDKs.

**Human-in-the-Loop & Learning from Rejections**

* **Dashboard:** A standard Next.js + Tailwind web app (or a view in the mobile app) pulling state from your database.
* **Learning Architecture:** When a user clicks "REJECT" on a clip, take the transcript of that clip, generate an embedding, and store it in a cheap vector database (like Pinecone or Supabase pgvector). During the *Highlight Detection* phase, do a similarity search against the rejected clips and instruct the LLM: *"Do not select clips semantically similar to these rejected examples."* This creates a customized preference model with zero fine-tuning.

**Security & Failure Modes**

* **Failures to map:**
* *TUS Server Crashes:* Trigger.dev task suspends, mobile client pauses, auto-resumes on server reboot.
* *LLM Context Limit:* Chunk the transcript before sending it for highlight detection.
* *Duplicate Upload:* TUS fingerprinting prevents this natively.


* **Privacy:** Use row-level security (RLS) in your database. Ensure Cloudflare R2 buckets are completely private, generating temporary signed URLs only when the worker needs to download the raw file or the user needs to preview the clip.

**Phased Execution**

* **V0 (Proof of Concept):** Manual upload via web dashboard. Server runs Whisper, passes to an LLM to identify timestamps, and uses FFmpeg to cut a standard 16:9 clip.
* **V1 (Usable System):** Introduce the mobile app with TUS background uploading. Add MediaPipe for automatic 9:16 cropping and FFmpeg `.ass` subtitle burn-in. Implement Trigger.dev to ensure jobs actually complete.
* **V2 (Autonomous Production):** Add the social media API publishing layer. Introduce the Human-in-the-Loop dashboard for one-click approval.
* **V3 (Learning Engine):** Implement the vector database rejection-learning loop so the system stops suggesting content the user dislikes.

**My Core Recommendation: If I were building this today**
I would use **React Native** (mobile client) → **TUS Protocol** (upload) → **Cloudflare R2** (storage) → **Trigger.dev** (orchestration) → **RunPod/Modal** (serverless GPU for WhisperX & MediaPipe) → **Gemini 1.5 Pro** (highlight logic) → **Ayrshare** (publishing).

Do not build the upload protocol; use TUS. Do not build custom UI for manual timeline editing; Relay is an autonomous engine, not a web-based Premiere Pro. Do not build OAuth integrations for social media platforms; use an aggregator. Focus 100% of custom engineering on the logic connecting the transcript to the FFmpeg exact cuts.
