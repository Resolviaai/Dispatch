## CRITICAL

### C1. Forged-Origin authentication bypass on the local dashboard — FIXED (test + live)
- **Where:** `dispatch/web/app.py` `verify_dashboard_auth`, former lines 161–171.
- **Impact:** any LAN client could send `Origin: https://appassets.androidplatform.net` and pass auth on every protected route (trim, approve, credentials, uploads) while the server was LAN-exposed — full dashboard takeover.
- **Evidence:** code review + reproduced: forged-Origin POST accepted pre-fix; after the fix the same request returns 403 against the running server.
- **Fix:** origin-only trust removed entirely. The native WebView already authenticates via the paired device token (`DispatchNativeBridge.getAuthToken` → `x-auth-token` → `verify_token`); loopback browsing unchanged (Host + Origin validation retained).
- **Verified:** `tests/test_dashboard_auth.py` 5/5; live `POST /api/clips/.../trim` with forged Origin → **403**; server restarted loopback-only (PID 36124, dashboard 200).

### H3. R2 ignores signed content-length on presigned PUTs — DOCUMENTED (live)
- **Evidence (live):** a 65-byte body against a 64-byte-signed URL was **accepted** by real R2 (HTTP 200).
- **Mitigation (live-verified):** `/complete` rejects actual > reserved (HTTP 422) and deletes the staging object; accounting holds reserved bytes until cleanup confirms. Signed header retained as defense-in-depth. The 10 GB global cap is therefore an **application-level** cap: physical bytes can transiently exceed tracked accounting for the URL-expiry window — no R2-native mechanism can prevent this (bucket storage is officially "Unlimited").
