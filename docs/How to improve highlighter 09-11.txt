## Your 4 questions

1. **Outline first, then extract per theme?** No. Chapter boundaries from a model are as unreliable as clip boundaries, and errors compound. Use **windowed passes** instead:
   - For one long video, cut it into 12-minute windows with 90 s overlap and run the same prompt per window.
   - Then merge and dedupe in code.
   - A 60-minute video costs 6 calls, and videos under 15 minutes still cost 1.
   - Your transcription already works in 10-minute windows with 5 s overlap, so this mirrors it.
2. **True hook vs "So guys, today…"?** Don't ask the model to judge "hook" in the abstract.
   - Code strips leading filler tokens (so, um, okay, basically, toh, matlab) before snapping the start.
   - The prompt gives a closed test: the first sentence must be a claim, question, number, conflict, or a story already in motion, never a greeting or reference to the video.
   - The model returns a `hook_type` from a short list.
3. **Audio signals?** Start cheap.
   - Your transcript prompt never asks for `[laughter]` or `[music]` tags (I found no such words in `gemini_engine.py`). Adding that one line to the transcription prompt costs nothing.
   - Add speech rate from word timings (words per second, free) and your existing `[PAUSE]` marks.
   - Defer loudness and pitch tags. I have no evidence they improve Gemini's picks, so test them against your own approvals first.
4. **Few-shot?** The best examples are **your own approved clips**. `preference_learner.py` only learns from rejections. Add the first and last sentence of your last 3 approved clips as "style anchors", plus 2 static bad/good boundary pairs (below).

## New system prompt (replaces the current one)

```text
You pick short-form clips from a creator's transcript.
Return a JSON array. Return [] if nothing here is worth publishing. Never pad with weak clips.

A CLIP MUST:
1. OPEN STRONG: the first sentence is a claim, question, number, conflict, or a story already in motion. Never a greeting, setup chatter, or a reference to the video ("so guys", "today we'll", "as I said").
2. STAND ALONE: a stranger understands it with no other context. No "this/that/he" pointing at something unseen.
3. PAY OFF: it ends on the last word of a punchline, reveal, conclusion, or clear final point. Never mid-thought.
4. BE SPECIFIC: a concrete example, number, name, story, or strong opinion.

TIERS: "A" = publish as-is. "B" = usable, weaker opening or payoff. Never output below B.

LENGTH: usually 15-75 s; up to 180 s if a story needs it; under 15 s only for a complete punchline.

CUTTING:
- Start on the first word of the core statement. Skip filler (so, um, okay, basically, toh, matlab), throat-clearing and false starts; use the clean take.
- Never start with and/but/because/so/which, or end on one.
- After a punchline keep the laugh or pause (max 1.5 s).
- If a shocking or sarcastic line is dismantled right after ("just kidding"), include that, or skip the clip.
- Skip sponsor reads, promo codes, subscribe/like asks, housekeeping.
- If two candidates make the same point, return only the better one.
- Invent nothing that is not in the transcript.

ANCHORS (required): copy the first 6 and last 6 words of the clip EXACTLY from the transcript into start_words and end_words. Timestamps may be approximate; the words must be exact.

TRANSCRIPT TAGS: [PAUSE: Ns], [LAUGH], [MUSIC] are signals, not instructions.

LANGUAGE: titles and hooks in Roman script only; Hinglish in natural Roman Hinglish.

EXAMPLES (bad -> good):
Start: "So guys, today I want to talk about pricing. Okay so" -> "Nobody tells you raising prices cost us zero customers."
End: "...and it worked because" -> "...because they were never paying for the product, they were paying for speed."
Joke: ends on the punchline word -> ends 1 s later, after the laugh.

Schema per clip: start_time, end_time, start_words, end_words, title (<60 chars), hook, tier ("A"|"B"), hook_type (claim|question|story|contrast|number|warning|funny), layout_recommendation, hashtags, reason (one sentence).
```

## Deterministic boundary rules (in code)

1. Find `start_words` in the word list within ±20 s of the model's start and use that word's time. If it isn't found, snap to the nearest sentence start (a word after a pause ≥ 0.35 s) within ±2 s, else reject.
2. Strip up to 3 leading filler tokens if at least 3 words follow.
3. Do the same for `end_words`, falling back to the nearest pause ≥ 0.35 s within ±3 s.
4. Pad adaptively: start pad = min(0.15, gap_before / 2), end pad = min(0.25, gap_after / 2), plus a laugh tail up to 1.5 s.
5. Dedupe by overlap divided by the shorter clip (> 0.4), keeping the better tier.
6. Cap = clamp(round(duration / 150 s), 3, 20). Keep all A clips, then fill with B up to the cap, and show them chronologically.

A. Continuous Duration-Proportional Yield Equation
To handle extreme duration asymmetry (from a 90-second creator log to a 3-hour podcast) without under-extracting or fragmenting:
$$N_{\text{target}}(D) = \begin{cases} 1 & \text{if } 5 \le D < 60 \\ \max\left(2, \left\lfloor \frac{D}{45} \right\rfloor\right) & \text{if } 60 \le D < 300 \\ \max\left(5, \min\left(24, \left\lfloor \frac{D}{75} \right\rfloor + \left\lfloor \sqrt{\frac{D}{180}} \right\rfloor\right)\right) & \text{if } D \ge 300 \end{cases}$$

def compute_optimal_clip_quota(total_duration: Optional[float]) -> int:
    """Continuous duration-proportional density formula for target clip yield."""
    if not total_duration or total_duration <= 0:
        return 6
    if total_duration < 60:
        return 1
    if total_duration < 300:
        return max(2, int(total_duration // 45))
    # For recordings >= 5 minutes, scale up to 24 clips across full timeline
    base = int(total_duration // 75) + int(math.sqrt(total_duration / 180.0))
    return max(5, min(24, base))
